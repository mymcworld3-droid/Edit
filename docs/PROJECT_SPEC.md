# 專案規格與背景介紹

## 1. 專案名稱

**《誰讓他修仙的！》角色戰績 Edit：從荒誕日常到仙人級壓迫感**

## 2. 專案目的與觀眾

製作一個可編輯、可播放、方便錄屏製作短影音的網頁，主題是小說《誰讓他修仙的！》（作者：最白的烏鴉）的角色**戰績**。不是劇情懶人包、排名表、普通角色卡或圖片輪播。

觀眾包括未讀小說的人，因此要求「每個戰績的可理解性」優先於堆砌術語。觀眾要在短短數十秒內感受到：角色前期荒唐又好笑，後期卻有撼動世界規則的實績。

## 3. 人物與重點

- **陸陽**：劍修，從問道宗少年修至劍仙；前段強調臥底、假天庭教、魔教燒烤事業；後段強調無敵丹／溯源道果與兩條時間線的決戰。
- **黃豆豆**：不朽仙子，上古五仙之一；前段強調被復活後寄居陸陽精神空間、廚藝反差；後段強調四十萬年前的仙人之死造成星空封鎖，以及不朽道果與灰豆豆的衝突。
- **雲芝**：問道宗大師姐，半步合道；前段強調管教師父、整頓宗門；後段強調鎮壓上古強者、與超脫境敵手交戰。**她適合最後壓軸**。
- 可選客串：孟景舟；不要稀釋三位主角的篇幅。

## 4. 核心敘事結構（約 30–35 秒，可變）

| 段落 | 參考區間 | 內容 | 節奏 |
|---|---|---|---|
| 片頭／境界 | 0–5 s | 三位角色輪流登場：名字、身分、境界 | 節制而有質感 |
| 不正經戰績 | 5–14 s | 每句一個真正發生或可直接理解的荒唐事件 | 快速、俏皮、卡拍 |
| 轉折 | 14–16 s | 畫面抽黑、短暫停頓，提示真正戰績即將開始 | 反差極大 |
| Drop 高潮 | 16–31 s | 每個重拍出一條「具體事件 + 震撼結果」的真戰績 | 暗色、重低音感、空間尺度升級 |
| 結尾 | 31–35 s | 三人剪影同框，小說書名，最後一拍定格 | 凝聚、乾淨 |

**以上時碼僅為 placeholder。實際 Drop 與節拍請透過合法提供的本機音檔校準，禁止假裝已精準分析 Spotify 音樂。**

## 5. 音樂同步

- 指定歌曲：Spotify 連結見 `START_HERE.md`，為 〈Wannabe〉— why mona；使用者口頭稱「Wanna」。
- 不直接盜抓或繞過 Spotify 取得歌曲，不內嵌未獲授權音訊。
- 提供 **使用者選擇本機音訊檔**：`<input type="file" accept="audio/*">` + `URL.createObjectURL`。
- 提供時間軸編輯：各 scene 的起點、結束點，尤其 **Drop 秒數與音樂起播偏移 offset** 可調。
- 運動效果以 `audio.currentTime` / `requestAnimationFrame` 絕對時間驅動；不要只依賴一串 `setTimeout`，避免暫停／拖曳／重播不同步。
- 支援播放、暫停、跳轉、重設、循環及音量調整；聲音沒有載入時可無聲預覽動畫。
- 可選：BPM 節拍標記、可手動拖動的 marker、波形顯示（若要做精準音訊分析，必須以使用者提供的檔案為基礎）。

## 6. 畫面與視覺品質（硬性）

- 9:16，建議以 1080 × 1920 為邏輯設計稿；網頁可等比例縮放至桌面或手機。
- **禁止位圖人物、照片、AI 生圖當素材。** 全面用 SVG／Canvas 向量剪影。
- 剪影必須是**精緻而可辨識的古風人形**：不能只是圓頭、長方形身體、火柴人。
- 陸陽：細長劍、少年道袍、束髮／髮帶、劍光。
- 黃豆豆：嬌小而飄逸、長髮、飾帶、古仙環、不朽金光。
- 雲芝：高挑、長髮長袍、寬袖、冷白光、極低動作量但強烈壓迫。
- 同一人物所有場景保留同一份剪影骨架，只改姿勢／鏡頭／光效，不可形象跳動。
- 前段偏暖金、柔光，略帶幽默；高潮切到黑金、冷白與深藍，強烈尺度對比。
- 利用**多層視差、筆畫顯露、遮罩掃光、裂空、劍氣、粒子、星軌、鏡頭推進／拉遠**，但不能讓字幕難讀或過度閃爍。
- 高潮建議「一個重拍、一個具體戰績、一個絕對視覺結果」；不要每一秒都套同樣的閃白模板。
- 文字採繁體中文，可輔以小量英文 UI；重要文字一屏至多 1–2 行，主字級需適合手機觀看。
- 無控制按鈕進入最終錄製畫面；編輯工具條可隱藏。

## 7. 網頁功能規格

### 必須

1. 可以直接執行的網頁（`index.html`，必要時拆 `style.css`、`app.js`）。
2. 配置驅動的分鏡清單：每段 `start/end/character/phase/text/effect` 可集中編輯，不能把整段劇情寫死在不易修改的 JS 裡。
3. 9:16 錄製視窗，以及可隱藏的編輯控制列。
4. 播放、暫停、重新播放、拖曳進度、任意時間跳轉、逐段預覽。
5. 匯入使用者本機音檔；無音樂時依預覽時鐘播放。
6. 場景之間有實際動態過場，保證轉場可反向跳轉與重播。
7. SVG 向量人物與場景，不用網路圖片、不依賴外部 API。
8. 可見的時間標尺／目前時間，音樂 offset 與 Drop 時間可調。
9. 在瀏覽器操作時流暢，不發生黑屏、按鈕重複、時間軸抖動或文本超框。
10. 隨附 README，說明如何開啟、載音樂、校準、錄屏與修改內容。

### 加分

- 文字、角色、色彩、長度與 scene 排序可直接在 UI 修改。
- 手動 beat markers 與簡單波形輔助；如果實作音訊分析，須提示無音檔不能精準對拍。
- 支援手機直式預覽、全螢幕、進度快速鍵（空白鍵播放／暫停、方向鍵跳段）。
- 自動檢查 scene 重疊、留白與超時；缺少音訊時有明顯狀態提示。
- 簡化錄影流程。若宣稱可以一鍵 MP4 匯出，需真的能在瀏覽器環境產出，否則應改為錄屏指引。

## 8. 程式與交付要求

- 優先原生 HTML/CSS/JavaScript，或 Vue/React 均可，但需提供可執行完整專案和清楚安裝命令。
- SVG 元素重複使用／程式化生成，降低渲染成本。高頻動畫優先 `transform`、`opacity`。
- 使用 browser-supported 技術；不得假裝已自動取得 Spotify 音軌或自動找對拍。
- 禁止硬依賴訂閱 API 或在線 CDN 才能顯示人物。
- 構圖務必可錄屏，畫面主體不要被開發 UI 遮擋。
- 輸出**程式碼與檔案**，不要只輸出設計說明、圖片、Figma mockup。

## 9. 內容準確性

戰績必須是原著具體事件。內容草案見 `STORYBOARD.md`。對於原著發生的順序、戰績細節、境界及人物關係，要核對原著；無法核對時在配置中註記「待查證」，不要把粉絲誇飾寫成既定事實。
